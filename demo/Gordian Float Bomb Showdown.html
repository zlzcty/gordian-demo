Gordian Float Bomb Showdown
Gordian · target lb_float1_fp_l1 · 600 s budget

Seven LLMs vs. one floating-point logic bomb

We ran Gordian's lb_float1_fp_l1 benchmark with seven different models writing the ghost code. Six reached full coverage. They differed a lot in how fast they got there and how many tokens it took.

Claude Opus 5.5 · Sonnet 5.5 · Haiku 5.5 GPT-6.1 Sol (Codex) DeepSeek V4.1 Flash · gpt-oss-20b · Mistral Nemo

The verdict

▲ Best overall
DeepSeek V4.1 Flash
  • 13/13 lines in 43 s end to end, the fastest run. The bomb line was covered by the first harness, at 32 s.
  • One API call of 19.8 s using 9,481 tokens in total. The Claude Code runs used 440K to 1.5M.
  • Its first harness fixed s[0] = '7' before any float math ran. That is exactly the input the bomb needs.
▼ Worst
Mistral Nemo
  • The only model that missed the bomb: 12/13 lines (92.3%). Line 13 was never covered.
  • Its harnesses tried s[0] = '1', '2', '3' and then constrained s[1] and s[2], bytes the function never reads. It never tried '7'.
  • The fallback surrogate model failed to compile, and so did its repair. Gordian ran out of ideas.

Ranking rule: coverage first, then time until 13/13, then LLM effort (tokens, turns). Six models tie on coverage, so speed and efficiency decide the order.

Caveats

  • One target, one run each. This is a 13-line program. It shows whether a model spots the magic byte, not how it handles a parser or a math library. Run-to-run variance is unmeasured.
  • Two machines. The Claude runs were made on one machine (Oct 25) and the Codex/OpenRouter runs on another (Oct 23). Explore took 5–11 s on both, so the hardware gap is small next to the LLM-time differences.
  • Agents did more checking. Opus brute-forced every char in Python to prove '7' is the only trigger, then syntax-checked its harnesses in WSL. Single-shot API models can't run anything, so their speed partly comes from skipping verification.
  • Stray folders in the DeepSeek run. deepseek_v4.1_flash_1017/ was run in a directory left over from an earlier Mistral Nemo run (float1-nemo-1). So 02_rewrite/, 03_inversion/, coverage/02_model_*, variants/02_model_*, the triage files and LLM calls 0003–0005 make it look as if DeepSeek ran all three stages. It did not. Its report.json lists only the partition stage, its history ends at 01_partition_3, the leftover LLM files and usage.jsonl lines name mistralai/mistral-nemo, and 03_inversion/result.json is empty. DeepSeek reached 13/13 at 01_partition_1, so Gordian never started the later stages.
